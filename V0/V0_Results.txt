\chapter[PRELIMINARY RESULTS]{PRELIMINARY RESULTS}\label{sec.results}

We provide a concise overview of our progress towards completing RO-\ref{it.RO1}. We show our results of solving model~\eqref{form.milp} monotonically and our modified algorithm for solving the massive data set of 10.6 million patients. These results have been submitted as a paper titled \textit{``Identifying Most Lethal Cliques in Disease Comorbidity Graphs''} to the \textit{IISE Transactions on Healthcare Systems Engineering}. The paper is currently under review.
    
The original Bron--Kerbosch (BK) algorithm is a recursive algorithm that operates with three sets: a current clique $C$, set $L$ containing every candidate vertex  that may be added to enlarge clique $C$, and  set $S$ containing vertices that are adjacent to all vertices in $C$ but excluded as candidates for addition, in order to avoid outputting the same maximal clique multiple times during the recursive calls. The algorithm selects a vertex from $L$ and moves it to $C$. After updating $L$ and $S$ by removing the non-neighbors of the recently added vertex $v$, the recursive function is called with the new $C, L,$ and $S$. When $L$ and $S$ are empty, the current clique is returned as it is a  previously unreported maximal clique. Then, the algorithm backtracks to the most recent recursive call and the candidate vertex that was added is removed from the set of candidates $L$ and added to $S$ to help track for duplicates.
\begin{algorithm}[!htbp]
\small
    \KwIn{$\langle P, \widetilde{P}, A, G=(V,E), \ell, b\rangle$ and initial clique $C^0$ (possibly empty) such that $|C^0| < b$} 
    \KwOut{$K$ highest marginal mortality rate cliques with respect to $C^0$}
    $Q \gets \emptyset$ 
    \CommentSty{\hfill \small Global max-heap of cliques with mortality rate as priority}\\
    Insert $C^0$ in $Q$ with priority $\mu(C^0)$\\
    $C \gets C^0$, $L \gets V \cap \bigcap\limits_{u \in C^0}N(u)$, and $den \gets P\cap   \bigcap\limits_{u \in C^0} A_u$\\
    \SetKwFunction{FBronKerbosch}{Bron--Kerbosch}
    \FBronKerbosch{$C,L,den$}\\
    \KwRet{}  Top-$K$ cliques from $Q$\\

    \SetKwProg{Fn}{Function}{}{}
    \Fn{\FBronKerbosch{$C,L,den$}}{
     \If{$|C|=b$ \text{or} $L = \emptyset$   \label{step.terminate} } {\KwRet}
        \For{$v \in L$ \label{step.outer-for}}{
            $newden \gets den \cap A_v$\\
            \If{$|newden| \ge \ell$}{
                $\mu \gets \frac{|\widetilde{P} \cap newden|}{|newden|}$\\
                $C \gets C \cup \{v\}$\\
                \If{$C \notin Q$}{
                Insert $C$ in $Q$ with priority $\mu$\\
                }
                \FBronKerbosch{$C, L\cap N(v),  newden$}\\
            }
            $L \gets L \setminus \{v\}$\\
        }
        \KwRet %$Q$
    }
\caption{Enumerating top-$K$ highest marginal mortality rate cliques}
\label{alg.BKMMRC}
\end{algorithm}
Algorithm~\ref{alg.BKMMRC} is a variant of the BK algorithm that disregards maximality and instead includes pruning steps based on the following feasibility conditions: \textit{(i)}~restricting the enumeration to cliques of size at most $b$, and \textit{(ii)}~eliminating  cliques associated with insufficient patients by enforcing that $\left|\bigcap\limits_{u \in C} A_u\right| \ge \ell$. In Algorithm~\ref{alg.BKMMRC}, we use $N(v) \coloneqq \{u : \{u,v\} \in E\}$ to denote the neighbors of vertex $v$ in $G$.  

A global max-heap $Q$, prioritized by mortality rate, is used to store the enumerated cliques and $C^0$ is inserted in $Q$ initially. The disjoint sets $C$ and $L$ along with the set $den$, which represents the set $\bigcap\limits_{u \in C} A_u$ from the denominator of the mortality rate function are initialized next. Due to the recursive nature of the algorithm, it is more efficient to track and incrementally update $den$, rather than recompute it  each time. The current clique $C$ is initialized to $C^0$, the candidate set $L$ is initialized to the common neighbors of all the vertices in $C^0$ (or the entire vertex set if $C^0$ is empty), and $den$ is initialized to the set of patients that have all diseases in $C^0$ (or the entire patient set if $C^0$ is empty). 

The core of our algorithm is a recursion that is similar to the original algorithm in terms of enumerating cliques. However, as the mortality rate function is not monotonic, we must consider \textit{all cliques}, not just maximal cliques. Consequently, the set $S$ which is used in the original algorithm to avoid reporting the same maximal clique multiple times is not used in Algorithm~\ref{alg.BKMMRC}. Our algorithm terminates the recursion if one of the following conditions is met in Step~\ref{step.terminate} of Algorithm~\ref{alg.BKMMRC}: \textit{(i)}~when  $L$ is empty, which means that the current clique is maximal; or \textit{(ii)}~the size of current clique is $b$. As a clique is enlarged with the addition of a vertex $v$ in a recursive call, the set $den$ is updated, lower bound condition checked and if met, mortality rate is calculated. The new clique is inserted in $Q$ with its mortality rate as priority  if it is not already in the max-heap. Then a deeper recursive call is made with the updated sets. If candidate vertex $v \in L$ cannot be included due to the lower-bound $\ell$ not being satisfied, or if we added vertex $v$ and completed that recursive call,  vertex $v$ is removed from the set $L$. After the recursive calls are exhausted, the max-heap $Q$ contains all feasible cliques encountered, with their associated mortality rate as heap priority. We can now extract the clique with the highest marginal mortality rate and solve problem~\eqref{eq.MMRPclq}. More importantly, we can now return for any positive integer $K$, the cliques with the $K$ highest mortality rates. 

In our preliminary experiments, solving formulation~\eqref{form.milp} directly using the Gurobi solver was only viable up to \numprint{5000} patient dataset.  For larger instances, the solver terminated by reaching the three-hour time limit. Consequently, we employed a decomposition branch-and-cut (DBC) approach with delayed generation of constraints~\eqref{eq.wto0}--\eqref{eq.wtozUB}, which grow linearly with $|P|$, the number of patients in the dataset. In our preliminary experiments, we also considered delayed generation of constraints~\eqref{eq.xyconnectupperagg}--\eqref{eq.xyconnectlower} in combination with delayed generation of constraints~\eqref{eq.wto0}--\eqref{eq.wtozUB}, and by themselves, as this group of constraints also grows linearly with $|P|$. However, delayed generation of constraints~\eqref{eq.wto0}--\eqref{eq.wtozUB} produced the best overall performance for the MILP approach in our preliminary experiments.  The delayed addition of constraints was implemented in Gurobi using the ``lazy cut'' functionality. Whenever an integral solution to the linear programming (LP) relaxation is encountered at a branch-and-cut (BC) node, all violated constraints~\eqref{eq.wto0}--\eqref{eq.wtozUB} are added to the node as lazy cuts. Gurobi re-solves the LP relaxation and manages the tree node subsequently. At the root node, we begin with a relaxation that does not include any of the constraints~\eqref{eq.wto0}--\eqref{eq.wtozUB}.

 The results of solving formulation~\eqref{form.milp} using the DBC algorithm are documented in Table~\ref{tab:mipresults}. The columns labeled ``Sample'' and  ``$b$'' identify the test instance used and clique size upper-bound, respectively. Under the column labeled ``Clique'' we report the diseases corresponding to the best solution found. The column ``\#Exp'' reports the numerator of the mortality rate objective function and column ``$\mu$'' reports the mortality rate corresponding to the clique found. Recall that the denominator of every feasible clique should be at least size $\ell$, and we used a loose requirement of $\ell=10$ in this experiment.  The column labeled ``Gap (\%)'' reports the MILP termination gap, and it is zero whenever the solver finds an optimal solution. Under the column labeled ``Time (s)'' we report the wall-clock running time in seconds, rounded down to the nearest integer, for building the MILP relaxation used at the root node and solving it using the DBC algorithm. We also report the number of BC nodes enumerated under the column labeled ``\#BCN''. It is apparent from the results that despite using delayed   constraint generation technique, the MILP based approach is unable to solve any of the  instances with sample size \numprint{500000} to optimality (the entry ``TO'' denotes that the solver timed out).

By contrast, the modified BK Algorithm~\ref{alg.BKMMRC} is significantly faster on the same test bed and solves all instances to optimality as reported in Table~\ref{tab:allsamplesBK}. We still set the denominator lower bound $\ell = 10$ and  parameter $K$ to a value of 100. The wall-clock running time  reported here includes the time to complete all the recursive calls and the time to report the top-100 highest mortality rate cliques. The column labeled ``\#RC'' reports the number of recursive calls made by the algorithm. Although top-100 highest mortality rate cliques were found, for comparison purposes, we only report the maximum mortality rate clique found in Table~\ref{tab:allsamplesBK}.

From the foregoing experiments it is clear that due to the large number of patients in the data set and the small size of cliques we seek (from a graph with a few hundred vertices), the enumerative approach is dominant in its performance from a computational perspective. Furthermore, this approach also finds the top-$K$ most lethal cliques. Consequently, for our subsequent experiments and studies, we concentrate solely on the modified BK algorithm.

Our primary goal is to assess the performance of the modified BK algorithm on  the full dataset consisting of 10.6 million distinct patient records, as it represents the scale at which we may be interested in solving our problems of interest.  As evident from Table~\ref{tab:10mXBK}, the modified BK algorithm is effective on this large dataset for all practically meaningful values of parameter $b$. As far as the results themselves are concerned, the mortality rate associated with cardiac arrest, either by itself or in combination with other diseases stands out as the highest among all cliques of size at most 4. As expected the maximum mortality rate increases as the upper bound $b$ on clique size increases from 1 to 4. Cardiac arrest by itself has a mortality rate of 0.66, but when paired with coma, septicemia, shock, chronic ulcer, and respiratory distress syndrome, it corresponds to the five highest mortality rate cliques with $\mu$ ranging from 0.68 to 0.73. The mortality rates associated with cardiac arrest increase as expected for $b \in \{3,4\}$.
 
The results in Table~\ref{tab:10mXBK} have not revealed new insights of medical significance, as the  diseases featured in the five highest mortality rate cliques for each value of parameter $b$ are well-known within the medical community to be the most lethal comorbidities. However, the results do provide a verification of clinical insights through an analysis of large-scale EHR data. Furthermore, the fact that the proposed approach is  not detecting spurious comorbidities among its top-$K$ cliques is encouraging, as the detection of spurious clusters is a common concern in any graph-based data mining approach. The procedure followed in preparing  the dataset and the design of the modified BK algorithm seem to be offering a practically effective and useful framework for mortality rate analysis of comorbidities.

In order to explore the dataset further, we exclude from the 10.6 million patient dataset, every patient that has cardiac arrest, shock, aspiration pneumonitis, respiratory failure, or malignant neoplasm,  which may be evident to physicians as causing lethal comorbidities. The resulting dataset corresponding to 10.2 million patients is analyzed using the modified BK algorithm and the results are reported in  Table~\ref{tab:10mXBKdeletion}.

From the results  in Table~\ref{tab:10mXBKdeletion}, the individual mortality rate linked to secondary malignancies is the highest among all the (remaining) diseases, although it is much lower at 0.24. Notably, when paired with septicemia it corresponds to the highest mortality rate of 0.52, more than doubling mortality rate of secondary malignancies and more than the sum of the individual mortality rates. These two diseases continue to remain among the top-two highest mortality rate cliques when we increase $b$ to three and then to four, with the respective rates increasing to 0.58  and then to 0.63. 

This perspective into the mortality rates from the EHR dataset after excluding the  diseases well known to dominate mortalities provides an insight into how the proposed framework may be used to better understand lesser known comorbidities.  The findings presented in Tables~\ref{tab:10mXBK} and~\ref{tab:10mXBKdeletion} demonstrate that the modified BK algorithm is capable of tackling large-scale datasets within a reasonably short span of less than three hours. These results offer compelling evidence that our proposed methodology seamlessly integrates with real-world datasets, underscoring its robustness and effectiveness in practical healthcare analytics settings.

Our final experiment is to evaluate the modified BK algorithm when it is tasked to find maximum marginal mortality rate cliques. For this experiment, we consider the 10.2 million patient dataset described in the previous section that excludes every patient with any of the following diseases: cardiac arrest, shock, aspiration pneumonitis, respiratory failure, and malignant neoplasm. From Table~\ref{tab:10mXBKdeletion}, for each value of $b$, we fix the fifth highest mortality rate clique as $C^0$ and find the top-3 highest marginal mortality rate cliques when allowing the addition of one or two more diseases to $C^0$. We choose $C^0$ in this manner as the results in Tables~\ref{tab:10mXBK} and~\ref{tab:10mXBKdeletion} already demonstrate a sequence of containment relationships among the cliques as $b$ is increased. With the proposed design, we aim to identify high marginal mortality cliques not readily apparent from the results  in Table~\ref{tab:10mXBKdeletion}. 

As before, the modified BK algorithm is effective on the large-scale dataset we have considered, and it is extremely fast when  an initial clique of diseases $C^0$ is fixed. We can also see from the results in Tables~\ref{tab:margMRplus1t4} and~\ref{tab:margMRplus2t4} that this experiment offers information complementary to that reported in Table~\ref{tab:10mXBKdeletion}. Through this experiment we can recognize the disease(s) to be most wary of when a patient subgroup is already diagnosed with an existing clique of diseases, which is the main purpose behind investigating marginal mortality rates, to identify lethal comorbidities that are specific to the patient population under consideration.

% For RT 1-3, we have currently solved a version of this problem that identifies non-fault-tolerant $k$-clubs in the comorbidity graph $G$. Below, we present our algorithm along with its results.

%     The main idea behind enumeration $k$-clubs algorithm~\eqref{alg.MRkclub} in graph $G$ stems from the fact that every $k$-club is a $k$-clique. Where a $k$-clique is a subgraph where the distance between any two vertices is not greater than $k$. However, not all $k$-cliques are $k$-clubs because suppose $C^{'}\subset V(G)$ is a $k$-clique in $G$, each pair of vertices is connected by a path of length at most $k$, but that path may use any vertices in $G$. On the other hand, if $C^{'}\subset V(G)$ is a $k$-club, each pair of vertices must be connected by a path of length at most $k$ using only vertices inside $C^{'}$. An adjustment of a maximum clique algorithm, such as Bron--Kerbosch algorithm~\citep{BronKerbosch73}, permits the straightforward identification of a maximum $k$-clique within a graph G by examining its $k$-th power graph. The power graph $G^k$ shares identical vertex sets with $G$ and contains edges connecting any two distinct vertices $p$ and $q$ only if there exists a path of length no more than $k$ between them in $G$. Hence, the maximum cliques in $G^k$ align with the maximum $k$-cliques in $G$. Thus, we first find $k$-cliques in graph $G$ and then filter $k$-clubs from them.

% Algorithm~\eqref{alg.MRkclub} begins with receiving the set of all patients $P$, expired patients $X$, adjacency list of each disease $v$, $A_v$ that contains all patients suffering from disease $v$. Additionally, parameters $k$, $b$, and $S$ correspond to the diameter of $k$-club, the size of the $k$-club, and the size of the heap, respectively. We define a global priority queue~\citep{AhujaBook} with a mortality rate as priority to save top $S$ $k$-clubs in the graph $G$. Algorithm starts with the initialization of disjoint sets: $C$, $L$, $S$, and $den$. Set $C$ represents the current potential clique being explored. Set $L$ represents the set of vertices that can potentially be added to $C$. Set $S$ represents the set of vertices that have already been ruled out as potential additions to $C$. In order to incrementally compute the objective function from the parent node's information, we introduce set $den$. The denominator set $den$ initially contains all patients in our dataset. The modified BK employs a recursive approach at its core. Since the objective function ($\mu$) is not monotonic, we must consider all cliques in $G^k$. The algorithm terminates when the size of the size of the clique reaches $b$ ($|C|=b$) and it has the property of being a $k$-club (each pair of vertices in $C$ is connected by a path of length at most $k$ using only vertices inside $C$). The idea behind checking the $k$-clubness is based on doing a breadth-first-search (BFS) instead of making a subgraph $G[C]$ and calculating its diameter. For all vertices in $C$, we do BFS to check two properties. First, the longest path from a vertex $p$ in $C$ to all other vertices $q \in C$ ($p\neq q$) has the length at most $k$ using only available vertices in $C$. Second, $C$ is connected.

% The recursive step of the algorithm involves choosing a pivot vertex $v$ from $L$. If $C \cup \{v\}$ is a valid $k$-club in $G$, then algorithm calculates the mortality rate $\mu$ of $C \cup \{v\}$ and adds the $k$-club to the priority queue with its corresponding mortality rate. Next, it makes a recursive call to the BK algorithm in $G^k$.
